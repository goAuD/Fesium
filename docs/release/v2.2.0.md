# Fesium v2.2.0 - 2026-08-23

The hardening-and-handoff release. Nothing here adds a feature surface; what it does is close every way an independent security review could find past the local server's protections, make the diagnostics copyable, and write down the decisions the next stretch of work rests on.

## Security

- **The dot-path filter can no longer be talked past.** The review found three routes: a double-encoded path (`/%252Eenv`) that decoded to a dot-file only inside the stdlib's own second unquote; symlinks and junctions inside a served project that led anywhere on the machine; and DNS rebinding, where a web page rebinds its own domain to `127.0.0.1` and reads responses same-origin. All three are closed - percent-escapes decode to a fixed point, requests must resolve inside the document root, and the Host header must name this server. On Windows, resolving also expands short names, closing the `GIT~1` route to a dot directory.
- **The PHP backend plays by the same rules.** `php -S` alone serves a document root raw, so `GET /.env` needed no trick at all there. A bundled `router.php` now applies the same fixed-point dot-path filter before falling through to the built-in handler.
- Findings, attack inputs and risk ratings: [docs/reviews/ox-alpha-review-2026-08-23.md](../reviews/ox-alpha-review-2026-08-23.md).

## Reliability

- **Starting the PHP backend waits until PHP is actually listening** before reporting success, so a backend that never comes up reports a failure instead of handing the user a connection error behind a green log.
- **The screenshots on the Pages site are sized against their column**, not the viewport, so they no longer overflow a desktop window or shrink below the body text on a phone.

## Added

- **A `Setup Report` in `Diagnostics`.** One button copies everything on the screen as plain text for a help request; home folders are shortened to `~`, and no credential can appear in it - the report prints a type that has no field for one, and a test pins that.
- **ADR 0002**: MySQL will be reached through the `Database` view Fesium already has, over PyMySQL, rather than by bundling or rebuilding an admin panel. The [handoff audit](../specs/2026-08-23-handoff-audit-and-continuation-plan.md) verified the plan against the code and set the order of work: engine seam first as a behaviour-preserving refactor, then the MySQL engine.
- **A GitHub Pages portfolio page**, generated from the app's own colour tokens so it cannot drift from the product it describes.

## Upgrade Notes

- **Nothing to do.** No configuration, data or command changed. `~/.fesium/config.json` is read and written exactly as before.
- The minimum Python is 3.10, unchanged. No new runtime dependencies; the PHP router ships inside the package.
- Local servers still bind `127.0.0.1` only. Requests whose Host header does not name the server are refused with 403 - if you proxy Fesium through another hostname locally, address it as `127.0.0.1` or `localhost`.
