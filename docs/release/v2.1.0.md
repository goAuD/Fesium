# Fesium v2.1.0 - 2026-08-22

The release that was planned as UI polish and turned into a rebuild of how the app looks and what it decides for itself. Nothing here changes what Fesium is for. What changed is that the interface now says what matters, the runtime follows the project rather than the machine, and several things that were true only by accident are now held by tests.

## Headline Changes

- **Every view is a bento grid.** `Overview`, `Server`, `Database`, `Diagnostics`, `Guide` and `Settings` are laid out as tiles sized by what matters, replacing stacks of equally weighted panels and the scrolling page bodies that came with them. `Database` used to push the SQL editor and its results below the fold; the table list now runs the full height and schema, editor and results share the rest.
- **The runtime follows the project, not the machine.** Fesium served with PHP whenever PHP was on `PATH`, so a plain HTML and JavaScript site was handled by a PHP process it had no use for. A project is served statically unless it actually uses PHP, and `Static Fallback` is `Static Server` in the `Server` view, because for such a project it is not a fallback.
- **The environment report follows the project too.** A site that never touches PHP is no longer told which PHP is installed, and a missing PHP is only flagged for a project that wants one. `Diagnostics` also names the binary it probed, since a machine can carry several and `PATH` decides.
- **A `Project Database` check in `Diagnostics`.** Fesium serves PHP but runs no database server, so a Laravel project pointed at MySQL used to start fine and fail on its first query with an error from inside the framework. Fesium reads the project's `.env`, checks whether anything is listening where it asks, and says so plainly. Only `DB_CONNECTION`, `DB_HOST`, `DB_PORT` and `DB_DATABASE` are read - never credentials.
- **`Settings` holds real preferences** instead of a placeholder: a default project folder, a reopen-last-project toggle and the default port, and it states in one line which folder the next launch will open.
- **A typeface chosen on evidence.** See below.
- **A brand that carries its own ground.** See below.

## Typography

The three bundled faces were never chosen - they were picked at the start of the project and kept. This release decides the question on a criterion instead: *can a beginner read it and not get it wrong?* Fesium is for students, which makes that the right test.

Five candidates were measured at 16px, the app's body size, on how far apart their confusable characters sit:

| Face | Mean separation | Worst pair | Score |
| --- | --- | --- | --- |
| Sora | 0.41 | `l` / `1` | 0.10 |
| IBM Plex Sans | 0.52 | `I` / `1` | 0.28 |
| Atkinson Hyperlegible | 0.51 | `rn` / `m` | 0.17 |
| Source Sans 3 | 0.62 | `I` / `l` | 0.08 |
| Public Sans | 0.59 | `I` / `l` | 0.25 |

Read the worst pair, not the mean: a reader is tripped by the one pair a face gets wrong, which is how Source Sans 3 takes the best average and is still disqualified.

**Atkinson Hyperlegible** now sets everything the app writes, with **JetBrains Mono** for the log and the SQL editor. It was drawn by the Braille Institute for character disambiguation and is the only candidate with a dotted zero - which is what a screen made of ports, process ids, row counts and paths needs. `Sora` and `IBM Plex Sans` are gone; one family plus a mono is enough, because size and weight already carry the hierarchy in a bento layout.

## Brand

The old mark set every stroke at `stroke-opacity="0.28"` in a neon cyan that predated the matte accent pass. Against GitHub's dark canvas that measured 2.12:1, under the 3:1 floor for a graphical object - and because the SVG was transparent and a README borrows the reader's theme, it measured **1.10:1 on GitHub light**, which is invisible to any visitor on the default theme.

The mark is now a solid tile with a tilted orbit and its nucleus knocked out, square because the app's own geometry is square. The README leads with a banner that bakes its dark ground in, so the header renders identically in either GitHub theme rather than borrowing one. `scripts/build_brand.py` emits the mark, the banner, the social preview and the app icons from one geometry definition, because hand-maintained assets are how the previous set drifted apart.

## Performance

- **Selecting a project went from 78.6ms to 1.7ms.** Every UI action was spawning `php -v`, and eleven handlers rebuild the views, so each click stalled the window. The probe is gone from that path and the app-facing summary is cached; `Diagnostics` re-probes when opened, which is the one screen where a stale answer would matter.
- **Starting a server no longer freezes the window for two seconds.** The port check connected to the port instead of trying to bind it, with no timeout, measuring 2047ms per call on Windows and up to twenty times that when scanning for a free port. Binding answers the question in 0.2ms.

## Security

- CI actions are pinned to full commit SHAs instead of mutable tags an owner can silently repoint.
- Semgrep now runs a full scan of `main` on every push and weekly. Only pull requests were diff-scanned, and a diff scan cannot close a finding on the default branch - five stayed open for ten days after the code causing them was fixed.
- `requirements.txt` pins exact versions. Semgrep's supply-chain analysis skips unpinned dependencies, so 17751 vulnerability rules were running against zero packages.
- Schema inspection binds the table name as a SQL parameter via `pragma_table_info()` instead of formatting it into the statement.
- Destructive-query detection sees through leading comments and `WITH ... UPDATE` CTEs, so read-only mode cannot be talked past with a comment prefix.
- The root launcher no longer `exec()`s the package `__init__` to read the version.

## Quality

- A cross-platform CI matrix (Ubuntu, Windows, macOS on Python 3.10-3.12) replaces the single-runner workflow, and `ruff` lint has its own job.
- `scripts/check_layout.py` drives the real views in a live window and measures legibility, settling and tile balance. The pytest suite is deliberately display-free and cannot see a layout bug; this release had two that only it caught.
- `scripts/capture_screenshots.py` produces the README images at exact colours and identical sizes, replacing a script that only opened a window to be photographed by hand.
- A contrast floor held by tests: every button and text-on-surface pairing clears WCAG AA.

## Upgrade Notes

- **Nothing to do.** No configuration, no data and no command changed. `~/.fesium/config.json` is read and written exactly as before.
- `python nanoserver.py` still works, and `~/.nanoserver/config.json` is still read once if no Fesium config exists. Both remain for the whole v2.x line - see [ADR 0001](../decisions/0001-preserve-nanoserver-compat.md).
- PHP is only needed for projects that use PHP. A plain HTML, CSS and JavaScript project is served by the built-in static server either way, and now says so instead of reporting a PHP version it never uses.
- The minimum Python is 3.10, unchanged, and CI runs that floor so the claim stays tested.
